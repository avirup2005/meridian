STEP 1: INGESTION

PDFPLUMBER OVER PYPDF2

We don't just extract strings. We extract bounding boxes. We map every single character's X/Y coordinate on the page.

Why? Because if you don't know exactly where the text is, you can't rebuild tables, and you can't tell the user "This number came from Page 42, Top Left."

Receipts start at the ingestion layer.

STEP 2: LAYOUT-AWARE PARSING

THE NARRATIVE TEXT

Standard paragraphs are grouped. Headers are attached as metadata. If a paragraph is under a "RISK FACTORS" header, the AI knows its context automatically.

THE TABULAR DATA

Rows and columns are strictly preserved. We convert grid structures into Markdown tables *before* embedding, ensuring the LLM sees the X/Y relationship.

STEP 3: SEMANTIC CHUNKING

1000 TOKENS / 200 OVERLAP

We don't cut paragraphs in half. We use semantic boundaries (newlines, periods).

Why overlap? Because if a sentence says "Consequently, it grew by 15%", and the previous chunk has the word "Revenue", an overlap ensures "Revenue grew by 15%" stays in the same context block.

> chunk_size = 1000
> overlap = 200
> chunking_status: OPTIMIZED

STEP 4: EMBEDDINGS

PYTORCH & SENTENCE TRANSFORMERS

We convert every chunk of text into a high-dimensional mathematical vector (an embedding). Words with similar meanings have vectors close to each other.

CPU OPTIMIZED

We explicitly compile PyTorch for CPU-only to run within Render's ruthless 512MB RAM free-tier limit. No heavy CUDA binaries crashing the server. Lean. Mean.

THE VECTOR DB: FAISS

FACEBOOK AI SIMILARITY SEARCH

Why FAISS? Because we don't need a bloated cloud database for a single-session PDF analysis.

FAISS builds an in-memory index of our vectors. When you ask "What are the risks?", it performs an L2 distance search across thousands of chunks in literally milliseconds.

METADATA FILTERING

When we do Multi-Document Smackdown (NVIDIA vs AMD), we don't want their vectors mixing.

Every chunk is tagged with metadata: { company: "NVIDIA", year: 2024, page: 14 }

We perform Namespaced Retrieval. The AI only fetches NVIDIA vectors when answering about NVIDIA.

NO CROSS-CONTAMINATION.

FAQ: IS THIS JUST A WRAPPER?

Q: Is this just a ChatGPT wrapper?

A: Absolutely not. We handle our own semantic chunking, embedding generation using PyTorch and Sentence Transformers, and vector indexing using FAISS locally. We only use Gemini for the final synthesis layer, strictly constrained by our RAG pipeline.

FAQ: MASSIVE FILES

Q: How do you handle massive 300+ page PDFs?

A: We use Layout-Aware parsing to break the document down logically (preserving headers, tables, and paragraphs), embed the chunks, and retrieve only the top-K relevant passages per query using Cosine Similarity. We don't shove the whole PDF into the context window.
